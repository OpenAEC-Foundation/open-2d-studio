Formula Engine vs Node-Based Editor

Twee fundamenteel verschillende paradigma's voor parametrisch ontwerp

Formula-based (huidige richting)
// I-Profiel parameters
height = 300
flangeWidth = height * 0.5
webThick = max(8, height / 40)
flangeThick = webThick * 1.5
radius = if(height > 200, 12, 8)
area = 2 * flangeWidth * flangeThick + (height - 2*flangeThick) * webThick
// Cross-object
beamOffset = @Kolom1.width / 2

A

Formula Engine + Properties Panel

Formules in een tekstveld per parameter. Krachtig, compact, snel te gebruiken voor ervaren gebruikers.

Voordelen

  • Snel te bouwen (weken, niet maanden)
  • Past in bestaand properties panel
  • Lage leercurve voor simpele cases
  • Compacte representatie, makkelijk te serialiseren
  • Bestaande parametric types direct migreerbaar

Nadelen

  • Complexe logica wordt onleesbaar in tekst
  • Geen visuele data-flow overzicht
  • Minder aantrekkelijk / modern
B

Full Node-Based Editor

Visuele node graph zoals Blender Geometry Nodes. Nodes voor input, math, geometry, output. Verbind met links.

Voordelen

  • Visueel overzicht van de volledige data-flow
  • Complexe logica blijft begrijpelijk
  • Zeer uitbreidbaar (nieuwe node types toevoegen)
  • Modern, aantrekkelijk voor gebruikers
  • Node groups = herbruikbare componenten

Nadelen

  • Enorm veel UI-werk (node canvas, links, zoom, pan, minimap)
  • 3-5x meer ontwikkeltijd dan formules
  • Overkill voor simpele parameter-aanpassingen
  • Grotere state footprint per object
C

Hybrid: Formula Engine nu, Node Editor later

Bouw de constraint graph engine met formules als fase 1. De DAG die je toch al bouwt IS de node graph — je voegt later alleen de visuele node UI toe als frontend.

Voordelen

  • Snel werkend systeem (fase 1 = formules)
  • De engine is al node-compatibel (DAG = node graph)
  • Node UI kan later zonder engine-rewrite
  • Gebruikers kunnen al parametrisch werken tijdens node UI-ontwikkeling
  • Risicospreiding: engine bewezen voordat UI-investering

Nadelen

  • Node UI is alsnog veel werk in fase 2
  • Moet bij engine-ontwerp al rekening houden met node-compatibiliteit
